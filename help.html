Getting Started

ForensicDVR is a court-ready forensic recovery tool for DVR and NVR evidence. It performs block-level, read-only acquisition and applies two independent recovery methods to maximise frame recovery while maintaining full chain of custody.

The tool operates exclusively in read-only mode. The evidence image is never modified.

Creating a New Case

You will need: Case ID (or leave blank for auto-generation), FIR number, case name, court/jurisdiction, investigating officer name, unit/police station, date of seizure, and the evidence image path or URL.

The dataset label classifies the evidence image source:

  • SYNTHETIC — Generated or simulated data (for testing)
  • PUBLIC-EXPORT — A publicly released dataset
  • REAL-DISK — An actual seized evidence disk

This label is shown on every page and embedded in every report for transparency.

The tool accepts raw disk images (.img, .dd), E01 (EnCase), Ex01, AFF4, and direct block device paths (e.g. /dev/sdb). The format is auto-detected unless you specify a vendor.

Analysis Pipeline

  1. Acquire Image — Block-level read. Write-block is confirmed. SHA-256 is computed and locked.
  2. Identify Format — The DVR/NVR proprietary format is detected.
  3. Index-based Recovery — File allocation tables and index structures are parsed.
  4. Carve-based Recovery — Signature-based carving finds deleted/overwritten frames.
  5. Tamper Checks — Hash verification, discontinuity detection, timestamp anomaly analysis.
  6. Generate Report — Court-admissible PDF with chain of custody.

Limitations

⚠️ Important: Read before use in court

This tool is a prototype developed for SIH26150. It must not be used as the sole basis for any criminal conviction or legal determination without review by a qualified forensic expert.

  • Encrypted DVR formats are not supported.
  • Proprietary firmware-level obfuscation may prevent recovery.
  • Formats from obscure or no-brand manufacturers may not be detected.
  • H.265/HEVC streams have limited index-recovery support (carving only).

The tool cannot recover frames that have been physically overwritten by new recordings. Once storage sectors are reused, original data is unrecoverable without specialized lab equipment. The concordance view shows frames recovered by each method separately so the examiner can assess reliability.

Tamper flags indicate anomalies, not confirmed tampering. Power failures, firmware bugs, and storage media errors can produce identical patterns. Each tamper flag includes a plain-language explanation and the forensic examiner must form their own opinion.

ForensicDVR is developed for SIH 2026 (Smart India Hackathon). It is not an official tool of any government agency. Reports generated by this prototype should be reviewed and countersigned by a qualified forensic expert before being submitted to a court.

Accessibility Statement

♿ Our Commitment

ForensicDVR is committed to making this tool accessible to all users, including those who use assistive technologies. We aim to conform to WCAG 2.1 Level AA.

What we've implemented

  • Visible 3px focus ring on all interactive elements
  • Full keyboard navigation — no keyboard traps
  • All images and icons have alt text or are marked as decorative
  • Colour is never the sole means of conveying information — every status has an icon and text label
  • Colour contrast meets 4.5:1 for text and 3:1 for UI components
  • ARIA live regions for toast notifications and dynamic content
  • Form fields have associated labels and descriptive error messages
  • Tables have captions and appropriate scope attributes
  • Modals and drawers trap focus appropriately
  • Prefers-reduced-motion respected — no auto-playing animations
  • Text can be resized to 200% without loss of content or functionality
  • Minimum 44×44px touch target size for all interactive elements
  • Hindi language text marked with lang="hi" for screen reader pronunciation
  • Skip to main content link at top of every page
  • High-contrast mode available via the top bar
  • Text size adjustment (A- / A / A+) persisted across sessions
  • All data charts have table alternatives

Known issues

This is a prototype. Some complex interactive components (e.g. the timeline zoom) may not have complete keyboard support. We are actively working on improvements.
